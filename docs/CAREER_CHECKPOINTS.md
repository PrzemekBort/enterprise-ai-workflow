# Career Checkpoints

> Ten plik nie jest częścią technicznej roadmapy projektu. Służy do pilnowania momentu wejścia na rynek, przygotowania rekrutacyjnego i certyfikatów.

## Cel
Nie czekać pełnych 24 miesięcy z pierwszym kontaktem z rynkiem.

Rozwój techniczny i projekt mają prowadzić do stopniowego przejścia w kierunku:
- Backend / Cloud Developer,
- Cloud Engineer,
- AI Engineer / Cloud AI Engineer,
- w dalszej perspektywie: AI / Cloud Solutions Architect.

---

## Miesiące 1–5
### Priorytet
- fundamenty,
- .NET,
- SQL,
- projekt.

### Rynek
- [ ] obserwuję ogłoszenia, ale nie zmieniam roadmapy pod pojedyncze oferty
- [ ] zapisuję powtarzające się wymagania rynkowe
- [ ] nie dokładam technologii tylko dlatego, że pojawiła się w jednej ofercie

---

## Miesiące 6–9
### Rynek
- [ ] regularnie przeglądam oferty Backend / .NET / Azure / Cloud
- [ ] porównuję wymagania z `COMPETENCY_MATRIX.md`
- [ ] identyfikuję 3–5 najczęstszych luk
- [ ] sprawdzam, czy projekt daje dowody praktyczne dla kluczowych kompetencji

### Cel
Zrozumieć rynek i kalibrować rozwój bez gwałtownej zmiany kierunku.

# Quarterly Career Review

Co około 3 miesiące odpowiedz:

1. Jakie role są dziś realnym kolejnym krokiem?
2. Jakich wymagań z ofert jeszcze nie spełniam?
3. Które braki są zgodne z roadmapą, a które są tylko „noise”?
4. Czy projekt daje dowód praktyczny moich kompetencji?
5. Czy powinienem już aplikować, zamiast czekać na „idealny moment”?
6. Czy mój kierunek nadal zwiększa liczbę dostępnych opcji zawodowych?

Zmiana głównego kierunku wymaga silnego uzasadnienia, nie chwilowego trendu.
